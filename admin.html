How to connect (one time, about 2 minutes)
  1. Open this GitHub page (sign in if asked). Make sure the heading says Fine-grained personal access token.
  2. In Token name type: New Delhi Darbar Menu
  3. Under Resource owner, choose anvra (the account that owns the menu).
  4. Under Expiration, choose No expiration (or 1 year).
  5. Under Repository access, pick Only select repositories, then click Select repositories and tick New-Delhi-Darbar-Menu. If you skip this, publishing fails with a “refused” error.
  6. Open Permissions → Repository permissions, scroll to Contents, and change its dropdown from “No access” to Read and write. This is the step most often missed.
  7. Click Generate token at the bottom, then copy it (it starts with github_pat_).
  8. Paste it in the box below and press Connect.
Publishing was refused — how to fix it
A “refused” message almost always means one of these. Re-create the token and check each:
  1. Contents is still “No access”. The token needs Contents: Read and write. Read-only is not enough to publish.
  2. The repository was not selected. Under Repository access the token must explicitly list New-Delhi-Darbar-Menu. “Public repositories” only grants read access and cannot publish.
  3. Wrong resource owner. The token must be created under anvra, the account that owns the repository.
  4. A classic token was used. Classic tokens need the full repo scope ticked. A fine-grained token is easier and safer.
  5. The token expired, or was revoked. Generate a new one.
You can check what a token is allowed to do at github.com/settings/tokens. Nothing is ever lost while this is being sorted out — your changes stay saved on this device, and the manual file downloads below always work.
